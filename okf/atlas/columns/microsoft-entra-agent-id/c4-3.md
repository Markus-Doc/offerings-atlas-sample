How [Microsoft Entra Agent ID](profile.md) addresses the [Delegation (OBO)](../../controls/c4-3.md) control. Researcher verdict: supported. Verification state: unverified. Agents may retrieve this page on the owner's acceptance of 2026-10-10, a proof-of-concept rule. No evaluator has checked it.

<!-- chunk: answer -->
## Answer

Evidence result: supported.

Agent identities support the OAuth 2.0 on-behalf-of flow, exchanging a user token audienced to the blueprint for a resource token carrying the user's identity and delegated permissions. Conditional Access evaluates the user's policies on each OBO exchange, and refresh tokens support background work in user context. Delegated permissions are preauthorised through inheritable permissions on the blueprint.

<!-- chunk: products -->
## Products

Microsoft Entra Agent identity platform, Conditional Access for agents

<!-- chunk: gaps -->
## Gaps

Child agent identities cannot obtain interactive user consent, so admin consent on the blueprint is required. Inheritance works only within one tenant. Delegation applies only to Entra-protected resources.

<!-- chunk: options -->
## Options

Use the sidecar /Validate and /AuthorizationHeader endpoints for OBO and apply the on-behalf-of Conditional Access template.
