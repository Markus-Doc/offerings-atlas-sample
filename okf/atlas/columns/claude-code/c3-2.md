## Answer

Evidence result: partial.

The client enforces tool policy itself: permission rules per tool and MCP tool, managed MCP allowlists and denylists, PreToolUse hooks that can allow, deny or rewrite input, sandbox egress allowlists, and the auto mode classifier, with a server-side probe that scans incoming tool results for suspicious content. Gateway policies can apply different settings per IdP group.

<!-- chunk: products -->
## Products

Permission rules, managed MCP controls, hooks, sandbox network isolation, auto mode classifier

<!-- chunk: gaps -->
## Gaps

Enforcement is client-side, not a separate gateway. No tool quotas or rate limits, no schema validation policy, and Bash rules match command text.

<!-- chunk: options -->
## Options

Pair managed permission rules with an enforced sandbox and a TLS-inspecting egress proxy, and use PreToolUse HTTP hooks to call an external policy service.
