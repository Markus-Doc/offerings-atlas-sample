## Answer

Evidence result: partial.

The Agent Gateway registers A2A agents with an agent ID, set in the Admin UI, the /v1/agents API or config.yaml. Calls can carry an X-LiteLLM-Agent-Id header for spend attribution, and JWT auth can bind tokens to registered agents. Agent records hold a name, URL, protocol version and agent card fields, but the docs do not describe a linked owner or release record.

<!-- chunk: products -->
## Products

LiteLLM Agent Gateway, virtual keys, JWT auth (Enterprise)

<!-- chunk: gaps -->
## Gaps

No documented owner or release linkage on the agent record. Attribution via X-LiteLLM-Agent-Id is a caller-supplied header. Workload identity for agents that call LiteLLM depends on the virtual key they hold.

## Options

Issue one virtual key per agent with owner metadata, and test whether a key can spoof another agent's X-LiteLLM-Agent-Id header.
