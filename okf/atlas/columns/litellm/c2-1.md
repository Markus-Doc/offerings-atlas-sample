## Answer

Evidence result: partial.

LiteLLM does not sequence agent workflows. It retries model calls, falls back across model groups and cools down unhealthy deployments. For agents it caps iterations and spend per session and offers an admin-fired kill switch webhook to stop an agent runtime.

<!-- chunk: products -->
## Products

Router fallbacks and retries, Agent Iteration Budgets, Agent Kill Switch

<!-- chunk: gaps -->
## Gaps

No workflow definition, task delegation or recovery of agent state. Retries apply per model call only.

<!-- chunk: options -->
## Options

Use an orchestration framework for sequencing and rely on LiteLLM for per-call retry and session caps.
