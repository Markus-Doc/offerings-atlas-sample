How [LiteLLM](profile.md) addresses the [Delegation (OBO)](../../controls/c4-3.md) control. Researcher verdict: supported. Verification state: unverified. Agents may retrieve this page on the owner's acceptance of 2026-10-10, a proof-of-concept rule. No evaluator has checked it.

<!-- chunk: answer -->
## Answer

Evidence result: supported.

For MCP servers, auth_type oauth2_token_exchange exchanges the caller's bearer token at the identity provider (RFC 8693, or Entra jwt-bearer OBO) and forwards only the scoped token. Tokens are cached per subject token and server, so users get separate tokens. JWT auth can set the end-user ID from a verified claim, which overrides any request value.

<!-- chunk: products -->
## Products

MCP OBO Auth, OIDC / JWT auth (Enterprise)

<!-- chunk: gaps -->
## Gaps

The A2A gateway does not automatically forward the caller's virtual key or end-user ID to backend agents. JWT auth needs an Enterprise licence.

<!-- chunk: options -->
## Options

Use OBO for MCP servers that accept identity provider tokens, and test that a request without a subject token is refused rather than falling back to a shared credential.
