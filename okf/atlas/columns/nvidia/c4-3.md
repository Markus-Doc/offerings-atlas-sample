## Answer

Evidence result: partial.

The per_user_mcp_client pattern gives each user a separate workflow instance and MCP client, and the user authenticates via OAuth2 so downstream MCP calls carry that user's token. Toolkit security considerations mention tools that use delegated authorisation from the user.

<!-- chunk: products -->
## Products

per_user_mcp_client, per_user_react_agent, mcp_oauth2

<!-- chunk: gaps -->
## Gaps

Documented only for MCP over streamable-http. No token exchange or delegation across multiple hops is described.

<!-- chunk: options -->
## Options

Use an identity provider that supports token exchange and test that downstream services see the end user identity.
