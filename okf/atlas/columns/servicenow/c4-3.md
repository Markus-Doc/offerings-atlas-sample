<!-- chunk: answer -->
## Answer

Evidence result: partial.

By default an agent runs as the dynamic user, meaning the invoking user or the calling workflow's user, and tools always run as dynamic users (Zurich and Brazil). Role masking limits the agent to the intersection of the invoker's roles and an approved list and never adds roles (Brazil). Propagation of the user's identity to external MCP or A2A services is not documented, and inbound A2A uses a service account.

<!-- chunk: products -->
## Products

AI Agent Studio dynamic user, role masking

<!-- chunk: gaps -->
## Gaps

OBO to external systems unclear. MCP OAuth Client Credentials grant uses an administrator token. Inbound A2A runs as a configured service account.

<!-- chunk: options -->
## Options

Use OAuth Authorization Code grants for MCP servers and confirm per-user tokens in testing. Map inbound A2A callers to narrow service accounts.
